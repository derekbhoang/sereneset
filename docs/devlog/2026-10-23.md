# Devlog — 2026-10-23

## Summary

Connected the API to PostgreSQL through Drizzle and integrated Better Auth with email/password authentication and its organization plugin. Added the initial database migration and end-to-end coverage for authentication and session handling.

## What I built / changed

- Added the API configuration and database dependencies, including NestJS Config, Zod, PostgreSQL, Drizzle ORM, and Drizzle Kit.
- Added a local PostgreSQL 18 service with Docker Compose, persistent storage, a health check, and root commands to start, stop, inspect, and connect to the database.
- Added an API `.env.example` and an environment schema for the database URL, port, runtime environment, auth secret, auth URL, and web origin. Standardized local ports to `3000` for the web app and `9000` for the API.
- Created a database service with a shared connection pool, connection and query timeouts, a startup connectivity check, and pool cleanup on shutdown or failed initialization.
- Added seven auth and workspace tables: `user`, `session`, `account`, `verification`, `organization`, `member`, and `invitation`. Included timezone-aware timestamps, membership uniqueness constraints, indexes, and foreign-key deletion rules.
- Added the initial SQL migration, Drizzle configuration, migration generation/application commands, and a Better Auth CLI configuration entry point.
- Mounted Better Auth under `/api/auth/*` through a Fastify bridge, preserving response status, headers, and session cookies. Configured credentialed CORS for the web origin.
- Expanded the end-to-end suite to start a disposable PostgreSQL container, apply migrations, and exercise sign-up, session lookup, sign-out, sign-in, incorrect-password rejection, and CORS preflight behavior.

## Decisions & why

- **Decision:** Use Docker Compose for local development and Testcontainers for end-to-end tests.
  - **Why:** Keep local data persistent while giving the test suite a separate database initialized from the committed migrations.
- **Decision:** Share the Better Auth factory between runtime integration and CLI configuration.
  - **Why:** Keep the Drizzle adapter, email/password setup, and organization plugin configured consistently.
- **Decision:** Forward auth requests through Fastify and share application setup between the server and tests.
  - **Why:** Exercise the same auth routing and CORS configuration in both paths.
- **Decision:** Add composite membership uniqueness constraints to the foundation schema.
  - **Why:** Prevent duplicate workspace membership and prepare an organization-scoped membership reference for later application tables.

## Problems & fixes

- **Problem:** Better Auth uses Web `Request` and `Response` objects, while the API runs on Fastify.
  - **Fix:** Added a bridge that serializes parsed request bodies, removes stale content lengths, forwards response bytes, and preserves each `Set-Cookie` header separately.
- **Problem:** A successful sign-out response alone does not demonstrate that the session was revoked.
  - **Fix:** Added a test that replays the original cookie after sign-out and expects no session. The incorrect-password test also checks that cookies from the failed attempt cannot authenticate the caller.

## Learned

I learned the purpose of the file naming conventions used in the API:

| File pattern | Purpose | Example in this project |
| --- | --- | --- |
| `.module.ts` | Groups related providers and controllers, imports dependencies, and exports providers for other NestJS modules to use. | `database.module.ts` provides and exports `DatabaseService`. |
| `.service.ts` | Holds reusable business logic or infrastructure behavior that NestJS can inject into other classes. | `database.service.ts` manages the PostgreSQL pool, exposes Drizzle, and handles connection startup and cleanup. |
| `.config.ts` | Defines settings for a tool or library. | `drizzle.config.ts` tells Drizzle Kit where the schema and migrations live and how to connect to PostgreSQL. |
| `.cli.ts` | Provides an entry point or configuration for command-line tooling. | `auth.cli.ts` loads environment variables and exports a configured Better Auth instance for its CLI. |
| `.routes.ts` | Defines and registers HTTP routes. | `auth.routes.ts` registers the Fastify auth routes and translates requests and responses between Fastify and Better Auth. |

These suffixes describe each file's role; the code and framework APIs inside the file determine its behavior.

- Cookie-based authentication needs both credentialed CORS configuration and a trusted web origin when the frontend and API use different origins.
- Applying migrations to a fresh test database lets authentication tests exercise the committed schema as well as the HTTP integration.
- Session tests should check which user a cookie authenticates and whether that cookie still works after sign-out.

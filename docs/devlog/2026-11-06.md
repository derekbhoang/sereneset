# Devlog — 2026-11-06

## Summary

Added reusable session and workspace guards for application routes, with server-side session validation and current membership checks. Added unit coverage and decorators that let controllers require workspace access and receive the authorized context.

## What I built / changed

- Added `SessionGuard`, which resolves the authenticated session through Better Auth using the incoming headers and `disableCookieCache: true`. It attaches the inferred `AuthSession` to the request and returns `401 UNAUTHENTICATED` when authentication is missing.
- Set `Cache-Control: private, no-store` on guarded responses and forwarded individual refresh and cleanup cookies, including cookies accumulated when Better Auth throws an API error. Authentication failures use the application error shape; other failures propagate.
- Moved the `AUTH` injection token into `auth.tokens.ts` so the module, routes, guards, and tests can share it without importing it from the module definition.
- Added `WorkspaceGuard`, which takes the user ID and active organization ID from the authenticated session and queries the current membership using both IDs. It returns `409 ACTIVE_WORKSPACE_REQUIRED` when no workspace is selected and `403 WORKSPACE_ACCESS_DENIED` when membership is missing.
- Added a readonly `WorkspaceContext` containing `userId`, `organizationId`, `memberId`, and the current membership role. Client-supplied organization and user IDs do not determine this context.
- Added `@RequireWorkspace()` to run `SessionGuard` before `WorkspaceGuard`, and `@CurrentWorkspace()` to retrieve the authorized context in a controller handler. Missing context in the parameter decorator raises an internal error to expose incorrect route wiring.
- Registered and exported both guards through `AuthModule`, and re-exported `DatabaseModule` for consuming feature modules. Added direct `better-call` and Fastify type dependencies used by the integration.
- Added session guard tests for authenticated and missing sessions, server-side lookup options, refresh cookies, cleanup cookies from null results and thrown errors, duplicate-cookie prevention, and error propagation.
- Added workspace guard tests for missing authentication or workspace selection, current owner/admin/member access, membership query scoping, removed membership, workspace switching, ignored client IDs, and database failures. Query compilation uses real Drizzle with only the database I/O boundary replaced.

## Decisions & why

- **Decision:** Keep session authentication and workspace authorization in separate guards, composed in a fixed order.
  - **Why:** Session-only routes can authenticate without requiring a workspace, while tenant routes can reuse both checks.
- **Decision:** Bypass the session cookie cache and query membership on each guarded request.
  - **Why:** Access must reflect the server-side session and current membership, including workspace changes and membership removal.
- **Decision:** Carry authorized identity and workspace values in a typed request context.
  - **Why:** Controllers can pass server-resolved IDs to services when creating organization-owned records and attributing their creators.
- **Decision:** Preserve infrastructure errors instead of converting every failure into an authentication rejection.
  - **Why:** Session storage and database failures need to remain distinguishable from invalid credentials or missing membership.

## Problems & fixes

- **Problem:** Converting a Better Auth authentication error into a NestJS exception could discard cookies that clear invalid session state.
  - **Fix:** Read the accumulated error headers through `kAPIErrorHeaderSymbol`, fall back to explicit error headers when needed, and forward cleanup cookies before translating the `401`. Use the accumulated headers as the source when present to avoid duplicating cookies.
- **Problem:** A session can still identify an active organization after the user's membership has been removed.
  - **Fix:** Recheck the membership using the authenticated user and active organization on every request. Tests cover a successful request followed by rejection with the same session when the membership query returns no row.
- **Problem:** Client input could attempt to substitute another organization or user.
  - **Fix:** Resolve both IDs from the authenticated session. Tests supply conflicting values through the body, query, route parameters, and headers and verify that the membership query still uses the session values.

## Learned

- The selected workspace is session context; current membership determines whether the user may access it.
- Cookie cleanup matters on rejected requests as well as successful session refreshes.
- A shared guard can establish workspace access, but each resource query still needs an organization filter and any action-specific permission checks.
- Testing real Drizzle query compilation with a mocked database boundary checks membership query scoping without requiring a PostgreSQL container.
